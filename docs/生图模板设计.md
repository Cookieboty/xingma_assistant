# 商品生图（宣传图）模板设计

> 代码：`backend/src/promo/promo.templates.ts`（模板 + prompt 构造器）、`promo.service.ts`、`garment-ref-prepare.ts`（**羊毛衫**专用参考图准备）、`image-gen.client.ts`；小程序 `pages/product/promo/`。
> 密钥只在 `backend/.env`（`IMAGE_GEN_BASE_URL / IMAGE_GEN_API_KEY / IMAGE_GEN_MODEL`），前端与文档不出现密钥。
> 品类：当前仅落地 **羊毛衫（knitwear）** 标准流程；鞋子/裤子/衬衣另立，见 TECH §6.2。

## 总体流程

商品详情 →「生成宣传图」→ **先选模板** → 按模板 `steps` 依次显示步骤（不需要模特的模板没有“选模特”步）→ 提交 job → 轮询进度 → 结果网格 →「保存到商品」（写 `media_assets` 并追加到商品 `coverMediaIds`）。

所有模板的 prompt 都由服务端组装，并统一追加约束：
- **服装不变**：颜色、织纹、纱线粗细、领型、袖长、版型、细节与参考图完全一致，不改色、不加图案；
- **不画文字**：无文字、字母、水印、logo。中文商品特征只作为 “reference only, do not render as text” 传入。
- **真实摄影感（PHOTOREAL）**：全模板追加：自然肤质毛孔、真实镜头景深、自然光、电商纪实摄影；禁止塑料皮/蜡像脸/CGI/插画/过度磨皮。

### 羊毛衫生图前准备（`prepareRefsForCategory('knitwear')`）

1. 识别全部商品参考图：挂拍 / 细节 / 不可用（原图不静默丢弃）  
2. 细节不够 → 挂拍切 6/9 宫格作补充细节  
3. prompt 标明每张参考图角色 + 英文硬约束  
4. 生图记录同时存 `promptZh`（中文原话）与 `prompt`/`promptEn`（英文最终）  
5. 非羊毛衫或读不全完整成衣 → **拒生**并返回中文原因

预设模特（`GET /api/promo/models`）：亚洲女 22-28 / 30-40 / 45-55，亚洲男 25-35 / 40-55；每项含 `avatar`（小程序包内 `/images/models/*.png` 头像）。向导用头像卡片选模特。以后可扩展为本地模特参考图（作为额外 reference 传入）。

## 各模板 prompt 要点

- **细节特写**：Macro close-up，聚焦织纹/罗纹/领口/袖口；浅景深；多张时要求不同裁切角度。
- **平铺/挂拍**：整件可见、无人；呈现方式 + 背景道具；柔和自然光；多张时要求轻微道具/角度变化。
- **模特上身**：`{模特描述} wearing the exact knit garment from the reference`；动作 + 场景；下装简洁中性不抢戏；真实皮肤比例；同姿态同场景多张时要求表情/重心等微变化，避免克隆。
- **多色展示**：同一模特、同一姿势与场景；选 N 色 → 出 N 张上身图（每张一色，非拼贴）。每张只喂该色参考图；颜色须匹配该色参考。无「张数」步，张数=颜色数。
- **小红书封面**：竖版 3:4、胶片感、温暖生活氛围；顶部留空白（不放字，后期再加标题）。无模特时忽略对人姿态、按静物处理；有模特时 `still` 不当作无人。

- **风格参考**：风格样例为构图/光影/氛围**硬参考**（`styleRefPrimary`）；商品图 KEEP 优先；上传后 vision 抽中文关键词（场景/有无模特/景别/氛围/背景）可编辑；分析失败可空关键词仍可生图；禁止从样例抄衣服/人脸/品牌。API：`POST …/promo/analyze-style-refs`。其它五模板的可选「风格样例」保留不变。

姿势与场景合并为一步 `pose_scene`（预设芯片 + 自由文本/语音）。自由描述经服务端 VISION LLM（失败则关键词启发式）拆成英文 pose/scene/mood 片段写入 prompt，自定义文案优先于芯片；KEEP/NO_TEXT 仍追加。

多张时动作/场景按选择轮换组合（第 i 张取 `poses[i % n]`，场景按组轮换）；`multi_color` 整组固定同一姿势与场景。

## 上游调用（aijws，实测 2026-10-21）

- `POST /v1/images/generations`（JSON，同步 b64_json，约 30–90s）：**会忽略 `image` 字段**，只能文生图 → 仅用于无参考图。
- `POST /v1/images/edits`（multipart，同步）：经常超过网关 ~55s 返回 **504**，不可靠，作为兜底。
- **原生异步任务（默认用于有参考图）**：`POST /v1/inputs`（声明 sha256/size）→ `PUT /v1/inputs/{id}/items/{itemId}` 上传原图 → `POST /v1/quotes` 报价 → `POST /v1/image/generations`（`model: image:gpt-image-2-free`，`mode: image-to-image`，`size: 1:1|3:4`，`resolution: 1K`，`maxAmount`=报价，`inputSessionId`、`imageInputIds`；**Idempotency-Key 必须等于输入会话的 requestId**，否则 404 INPUT_NOT_FOUND）→ 轮询 `GET /v1/tasks/{id}` → `GET /v1/tasks/{id}/content?index=0`。单张约 35–45s，报价 0.02 USD/张。
- 顺序可用 `IMAGE_GEN_REF_MODE` 配置（默认 `task,edits`）。并发 `IMAGE_GEN_CONCURRENCY`（默认 2，全局）。

## 后端 API（owner/staff）

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/promo/templates` | 模板列表（不含函数） |
| GET | `/api/promo/models` | 预设模特 |
| GET | `/api/promo/presets` | templates + models + sizes |
| POST | `/api/products/:id/promo/start` | 返回商品图片（assets，含 url）、颜色、特征草案 |
| GET/PUT | `/api/products/:id/promo/feature` | 特征草案读取/保存 |
| POST | `/api/products/:id/promo/generate` | `{templateId, feature?, referenceAssetIds[], modelId?, poses[], scenes[], colors[], count, sizeId}` → job（后台执行） |
| GET | `/api/products/:id/promo/jobs` | 最近 20 个 job |
| GET | `/api/products/:id/promo/jobs/:jobId` | 状态与结果 URL |
| POST | `/api/products/:id/promo/jobs/:jobId/save` | `{indexes?}` 存入商品图片 |

存储：结果图 `storage/tenants/{tenant}/products/{款号}/promo/{jobId}/NN.png`（经 `/media/` 提供）；job/特征 JSON 在 `backend/data/promo/`（不在静态目录内，已加入 .gitignore）。
